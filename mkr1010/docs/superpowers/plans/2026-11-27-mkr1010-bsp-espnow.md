# MKR1010 BSP + ESP-NOW Receive Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a BSP, scheduler, NINA ESP-NOW firmware and SAMD ESP-NOW driver for the MKR WiFi 1010, so it receives complete, verified radar frames from several ESP32-C3s on channel 6 without losing bytes during LED redraws.

**Architecture:** A portable C protocol library (`espnow_proto`) holds the CRC, the UART frame encoder/parser and the packet reassembly. The NINA sketch and the SAMD driver both use it, and so do the host unit tests. The BSP owns the pins, NINA control, the busy line, a millis-based cooperative scheduler and the 5 s idle-standby policy. The display driver wraps `show()` in the ESP-NOW driver's hold/release.

**Tech Stack:** Arduino C/C++, arduino-cli, cores `arduino:samd 1.8.14` (MKR) and `esp32:esp32 4.0.0` (NINA), Adafruit_NeoPixel (installed), gcc for host tests.

**Spec:** `mkr1010/docs/superpowers/specs/2026-11-27-mkr1010-bsp-espnow-design.md`

## Global Constraints

- ESP-NOW: channel 6, `WIFI_PROTOCOL_LR` only, ESP-NOW v1, broadcast receive.
- C3 packet: 3-byte header `[frame_seq, packet_index, packet_count]`, then up to 247 B. Packet i goes at offset i × 247. Max frame is 1024 B.
- UART frame: `A5 5A | len u16 LE | mac[6] | rssi i8 | payload | crc16 u16 LE`. The CRC covers len through the end of the payload and is CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF, no reflection, no final XOR). Overhead is 13 B.
- NINA↔SAMD UART: 460800 baud. NINA UART0 (`Serial`), SAMD `Serial1`.
- Pins: `NINA_RESETN` active-high (HIGH = held in reset), `NINA_GPIO0` HIGH at reset, busy = SAMD `NINA_ACK` (pin 35) output → NINA GPIO33 input, WS2812B data = pin 8.
- Reassembly slots: 4. NINA frame queue: 8, drop oldest when full. Scheduler: 8 jobs, 1 ms resolution. Idle timeout: 5000 ms.
- SAMD idle sleep is the CPU-only idle mode (`PM->SLEEP.reg = PM_SLEEP_IDLE_CPU` then `__WFI()`). Never deep sleep. Never change the CPU clock.
- No speedometer and no supervisor. Do not touch `mkr1010/src/debug/` or `mkr1010/docs/processing.md`.
- Comments are sparse: only real gotchas.
- Module folders are flat Arduino libraries: `.h/.c/.cpp` in the folder root, test sketches under `examples/`. Host tests live in `mkr1010/test/`, never inside a library folder, because Arduino would compile them.
- No commits unless the user asks. Work on branch `mkr1010-bsp` (create it from `main` before Task 1).
- The repo path contains `ð`. If arduino-cli fails on it, build through an ASCII symlink (e.g. `ln -s "/home/voxy/Projects/faðmr" ~/fadmr`) and run the same commands from there.

**Shared build command (SAMD)**, referred to below as `BUILD_SAMD <sketch>`, run from the repo root:
`arduino-cli compile --fqbn arduino:samd:mkrwifi1010 --library mkr1010/src/bsp --library mkr1010/src/espnow_proto --library mkr1010/src/espnow_drv --library mkr1010/src/display <sketch>`

**Shared build command (NINA)**, `BUILD_NINA`:
`arduino-cli compile --fqbn esp32:esp32:esp32:FlashSize=2M,FlashFreq=40,FlashMode=dio,PartitionScheme=minimal --library mkr1010/src/espnow_proto mkr1010/src/nina_fw`

## Review Focus

1. NINA boot log (115200 baud garbage at 460800) arriving before the first frame: the parser must skip it and still return the first real frame. Covered by Task 1 `test_garbage_prefix`.
2. A maximum-size 1024 B frame (5 packets, last one 36 B) must reassemble and pass through the parser. Covered by Task 2 `test_max_frame` and Task 1 `test_roundtrip_max`.
3. Two senders' packets interleaved must each produce their own frame with the right MAC. Covered by Task 2 `test_two_senders_interleaved`.
4. `millis()` wraparound at 2^32 must not stop or burst scheduler jobs. Covered by Task 3 `test_wraparound`.
5. `espnow_drv_hold()` with the NINA off or silent must return within 30 ms, never hang. Covered by Task 5 Step 3 (bounded wait) and hardware check H4.

### Task 1: Protocol library: CRC, encoder, parser

**Files:**
- Create: `mkr1010/src/espnow_proto/espnow_proto.h`, `mkr1010/src/espnow_proto/espnow_proto.c`
- Create: `mkr1010/test/test_proto.c`, `mkr1010/test/Makefile`

**Interfaces:**
- Produces (C, header wrapped in `extern "C"`):
  - `#define EP_MAX_FRAME 1024`, `EP_PKT_HDR 3`, `EP_PKT_PAYLOAD 247`, `EP_SYNC0 0xA5`, `EP_SYNC1 0x5A`, `EP_OVERHEAD 13`
  - `typedef struct { uint8_t mac[6]; int8_t rssi; uint16_t len; const uint8_t *data; } ep_frame_t;`
  - `uint16_t ep_crc16(const uint8_t *d, size_t n);`
  - `size_t ep_encode(const uint8_t mac[6], int8_t rssi, const uint8_t *payload, uint16_t len, uint8_t *out, size_t cap);` returns the bytes written, or 0 if `len > EP_MAX_FRAME` or `cap < len + EP_OVERHEAD`.
  - `typedef struct { uint8_t buf[EP_MAX_FRAME + EP_OVERHEAD]; size_t n; uint32_t bad; } ep_parser_t;`
  - `void ep_parser_init(ep_parser_t *p);`
  - `bool ep_parser_feed(ep_parser_t *p, uint8_t b, ep_frame_t *out);` returns true when `b` completes a verified frame. `out->data` points into `p->buf` and stays valid until the next feed.
  - `bool ep_parser_mid_frame(const ep_parser_t *p);` true while sync has been seen and the frame isn't complete yet.

- [ ] **Step 1: Write failing tests in `mkr1010/test/test_proto.c`** (plain `assert`, one `main` calling each test, prints `proto ok`)
  - `test_crc_check`: `ep_crc16("123456789", 9) == 0x29B1`.
  - `test_roundtrip_small`: encode a 10 B payload with mac `01..06` and rssi -40, then feed the bytes one at a time. Exactly the last byte returns true, and mac, rssi, len and payload match.
  - `test_roundtrip_max`: same with 1024 B. `ep_encode` with 1025 B returns 0.
  - `test_garbage_prefix`: 200 bytes of `"ets Jun  8 2016 rst:0x1 ..."`-style text containing one stray `A5 5A`, then a valid frame. Exactly one frame comes out, it's correct, and `bad >= 1`.
  - `test_bad_crc`: flip one payload byte. No frame, `bad == 1`. A valid frame fed afterwards comes out.
  - `test_false_sync_in_payload`: a frame whose payload contains `A5 5A`, preceded by a truncated frame (sync + header, then cut off). The parser recovers and returns the full second frame. This proves the resync restarts one byte after the false sync and doesn't skip the buffered bytes.
  - `test_len_too_big`: sync followed by len 0x0500. Rejected right at the header (`bad` increments) without waiting for 1280 bytes.
  - `test_mid_frame`: false before anything, true after feeding sync + 3 bytes, false after the frame completes.

- [ ] **Step 1: Add failing tests** (a helper splits a buffer into C3-style packets: header `[seq, i, count]` + 247 B chunks)

  - `test_rejects`: len < 3, count 0, count 6 (6 × 247 > 1024), index ≥ count, and a total longer than 1024 are each rejected (`rejected` increments) and return false.

### Task 3: BSP scheduler (portable core)

**Files:**
- Create: `mkr1010/src/bsp/bsp_sched.h`, `mkr1010/src/bsp/bsp_sched.c`
- Create: `mkr1010/test/test_sched.c`; Modify: `mkr1010/test/Makefile`

**Interfaces:**
- Produces (C, `extern "C"` header):
  - `#define BSP_SCHED_MAX_JOBS 8`
  - `typedef void (*bsp_sched_fn_t)(void *ctx);`
  - `uint32_t bsp_now_ms(void);` is declared here and implemented elsewhere: `bsp.cpp` uses `millis()`, the test uses a fake clock.
  - `void bsp_sched_init(void);` clears the table.
  - `int bsp_sched_add(bsp_sched_fn_t fn, void *ctx, uint32_t period_ms);` returns a job id (0..7), or -1 if fn is NULL, the period is 0 or the table is full. The first run is at `bsp_now_ms() + period_ms`.
  - `void bsp_sched_remove(int id);` ignores invalid ids.
  - `void bsp_sched_run(void);` runs every due job once. Next due = previous due + period, but if that's already in the past it becomes now + period, so there's no catch-up burst. Jobs may add or remove jobs during a run.

  - `test_remove_self`: a job that removes itself runs exactly once.
  - `test_add_from_job`: a job that adds another job. The new job first runs one period later, not in the same run.
  - `test_no_burst`: 10 ms job, jump from t=0 to t=100. One call, then the next call at t=110.
  - `test_wraparound`: start at t = 0xFFFFFFF0, 10 ms job. Runs at 0xFFFFFFFA and again at 0x00000004.

### Task 5: SAMD ESP-NOW driver

**Files:**
- Create: `mkr1010/src/espnow_drv/espnow_drv.h`, `mkr1010/src/espnow_drv/espnow_drv.cpp`
- Create: `mkr1010/src/espnow_drv/examples/espnow_dump/espnow_dump.ino`

**Interfaces:**
- Consumes: `ep_parser_*` and `ep_frame_t` (Task 1); `bsp_nina_on`, `bsp_nina_busy`, `bsp_activity`, `BSP_NINA_BAUD` (Task 4).
- Produces:
  - `void espnow_drv_init(void);` runs `Serial1.begin(BSP_NINA_BAUD)`, inits the parser, then `bsp_nina_on()`.
  - `bool espnow_drv_poll(ep_frame_t *out);` If a frame completed during hold is pending, it returns that first. Otherwise it reads `Serial1` until a frame completes (true) or no bytes are left (false). It calls `bsp_activity()` for each frame it returns. `out->data` is valid until the next poll or hold.
  - `void espnow_drv_hold(void);` busy HIGH, `delayMicroseconds(1000)`, then while `ep_parser_mid_frame()` keeps feeding bytes until the frame completes (stored as pending) or 30 ms pass. It returns immediately if a frame is already pending.
  - `void espnow_drv_release(void);` busy LOW.
  - `typedef struct { uint32_t rx; uint32_t bad; } espnow_drv_stats_t;` and `void espnow_drv_stats(espnow_drv_stats_t *s);`. The SAMD core can't detect `Serial1` overflow, so byte loss shows up as `bad`.

### Task 7: NINA firmware

**Files:**
- Create: `mkr1010/src/nina_fw/nina_fw.ino`

**Interfaces:**
- Consumes: `ep_reasm_*`, `ep_encode`, `EP_*` (Tasks 1–2).
- Produces: the firmware described in spec §1.
  - `setup()`: `Serial.begin(460800)`, GPIO33 `INPUT_PULLDOWN`, WiFi STA + disconnect, `esp_wifi_set_protocol(WIFI_IF_STA, WIFI_PROTOCOL_LR)`, `esp_wifi_set_channel(6, WIFI_SECOND_CHAN_NONE)`, `esp_now_init`, register the recv callback, and create a FreeRTOS queue of 8 items `{ep_frame_t meta; uint8_t data[EP_MAX_FRAME];}`.
  - The recv callback (`const esp_now_recv_info_t *info, const uint8_t *data, int len`; rssi from `info->rx_ctrl->rssi`) calls `ep_reasm_push`. On completion it copies the frame into the queue. If the queue is full, it receives (drops) one item first.
  - `loop()`: when an item is available and GPIO33 is LOW, `ep_encode` into a static buffer and write it with a single `Serial.write(buf, n)`. If GPIO33 is HIGH, leave the item queued.
